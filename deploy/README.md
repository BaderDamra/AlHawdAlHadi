# نشر الحوض الهادي على SmarterASP

المشروع يستخدم ASP.NET Core 10 وSQL Server. انشر ناتج `dotnet publish` عبر السكربت أدناه، وليس مجلد المشروع أو الواجهة وحدها.

## الملفات الجاهزة

- `artifacts/verified/publish`: نسخة جاهزة للاختبار، وتحتاج اتصال قاعدة الإنتاج قبل رفعها.
- `deployment-secrets/admin-credentials.json`: بيانات دخول الإدارة المحلية. احتفظ بهذا الملف على جهازك ولا ترفعه.
- `deploy/smoke_test.py`: اختبار نسخة النشر على قاعدة LocalDB مؤقتة ومنفصلة تُحذف بعد الاختبار.
- `deploy/verify_remote.py`: اختبار النسخة المنشورة عبر HTTPS. الخيار `--booking` ينشئ طلبًا تجريبيًا ويحذفه بعد التحقق منه.

## الاتصال والنشر

1. أنشئ قاعدة MSSQL باسم `alhawd` من لوحة SmarterASP. اختَر كلمة مرور خاصة بالقاعدة واحتفظ بها.
2. احفظ نص اتصال SQL Server الصحيح في ملف `deployment-secrets/sql-connection.txt` داخل المشروع. استخدم اسم الخادم واسم القاعدة واسم المستخدم الظاهرة في لوحة الاستضافة. لا تستخدم `(localdb)` في الإنتاج.
3. أنشئ الحزمة النهائية من PowerShell داخل مجلد المشروع:

```powershell
./deploy/Publish-SmarterAsp.ps1 -ConnectionFile ./deployment-secrets/sql-connection.txt
```

4. ارفع محتويات الحزمة الناتجة إلى الجذر المربوط بموقع `site1`، بحيث يكون `web.config` و`AlHawdAlHadi.Api.dll` في الجذر نفسه، ومجلد `frontend` بجانبهما. تأكد من خلو الجذر من موقع سابق أو خذ نسخة احتياطية منه قبل الاستبدال.
5. يحتاج حساب تشغيل الموقع صلاحية الكتابة في `frontend/images/uploads`. لا تمنح المستخدمين الآخرين صلاحية الوصول إلى ملفات الإعدادات.
6. استخدم HTTPS. الإدارة على `/admin`، وبيانات دخولها في الملف المحلي المذكور أعلاه. تعالج قاعدة البيانات migrations وتهيئة محتوى الموقع عند التشغيل الأول، لذلك يجب أن يكون مستخدم قاعدة البيانات مخولاً بإنشاء الجداول داخل هذه القاعدة.
7. تحقق من الرئيسية وصفحة المشروع و`/api/cms` وتسجيل دخول الإدارة وطلب حجز جديد.

## النشر اللاحق من Visual Studio

ملف `backend/AlHawdAlHadi.Api/Properties/PublishProfiles/SmarterASP.pubxml` جاهز لهذا الحساب. إذا كانت نافذة إنشاء ملف نشر جديد مفتوحة، أغلقها بـ Cancel ثم أغلق تبويب Publish وافتحه مجددًا من قائمة المشروع. اختر الملف الموجود باسم **SmarterASP**.

الملف يضبط عنوان Web Deploy والموقع واسم المستخدم `alhawd-001` وإصدار .NET ووضع OutOfProcess. يحافظ على ملفات السيرفر الإضافية، بما فيها الصور المرفوعة من لوحة الإدارة، ولا يغيّر ACL عبر Web Deploy. كلمة مرور Web Deploy غير مضمنة؛ أدخل كلمة مرور النشر الصحيحة عند طلبها. كلمة مرور SQL وبيانات إدارة الموقع منفصلتان عنها، ولم نتحقق من كلمة مرور Web Deploy للحساب.

عند النشر يقرأ الملف إعدادات الإنتاج المحلية من `deployment-secrets/appsettings.SmarterASP.json` ويضعها في `appsettings.Production.json` داخل الحزمة. هذا الملف موجود على الجهاز الحالي ومستبعد من Git. إذا كان مفقودًا، يتوقف النشر برسالة واضحة قبل الإرسال بدل نشر اتصال LocalDB. سكربت نشر ZIP يحدّث هذه النسخة المحلية عند تشغيله مع `-ConnectionFile`.

اختُبر تجهيز الملفات بهذا الملف محليًا دون إرسالها إلى الاستضافة، وتأكد تضمين الواجهة وإعدادات الإنتاج وIIS والمحتوى الحالي واستبعاد إعدادات التطوير والحجوزات التجريبية. اختبار وصول عنوان Web Deploy نجح مع التحقق من الشهادة؛ تسجيل الدخول إلى Web Deploy لم يُختبر لعدم معرفة كلمة مرور النشر.

## سلوك نسخة الإنتاج

- تضم النسخة الواجهة والصور الحالية وتهيئة IIS بوضع OutOfProcess.
- تُستخدم تعديلات `runtime-cms.json` الحالية كمحتوى أولي للقاعدة الجديدة.
- لا تُضاف الحجوزات التجريبية في الإنتاج، ولا تُنقل حجوزات LocalDB الحالية تلقائيًا.
- عرض المحتوى وإرسال الحجز متاحان للزوار. قراءة الحجوزات وإدارة المحتوى والصور تتطلب تسجيل الدخول.
- ملف إعداد الإنتاج يحتوي على اتصال القاعدة وتجزئة كلمة مرور الإدارة؛ لا تشاركه أو تضفه إلى Git.
- `deployment-secrets/` و`artifacts/` مستبعدان من Git.
- يضبط سكربت النشر IIS ليسمح بعرض الواجهة العامة للزوار ويستخدم تسجيل دخول التطبيق للإدارة. الإعدادان اللازمان لهذا الموقع هما `anonymousAuthentication enabled="true"` و`basicAuthentication enabled="false"` داخل `system.webServer/security/authentication`.

اختُبرت النسخة محليًا بنجاح: تشغيل ملفات النشر عبر dotnet، migrations، المحتوى، الحجز العام، دخول الإدارة، منع الوصول المجهول، وحماية التعديل من مصادر أخرى.
